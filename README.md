# ORIGIN Ring Studio

Лендинг с историей кольца и параметрический 3D-конструктор. Ветка `main` сохраняет предыдущую итерацию; развитие конструктора — `feature/ring-constructor-studio`.

## Запуск

Нужны Node.js 20+ и Python 3.9+.

```sh
npm ci
python3 -m pip install -r requirements.txt
npm run build
cp .env.example .env
# Впишите DEEPSEEK_API_KEY в .env
npm start
```

Открыть http://localhost:8765/. Предсобранные `app.js` и `chunks/` включены в Git, поэтому для просмотра достаточно `npm start`. Сервер слушает только `127.0.0.1`.

## Возможности

Пять шагов: шинка, центральный камень, оправа, детали, итог. Расширенные варианты раскрываются отдельно. 12 шинок, 5 профилей, 12 материалов камня, 12 огранок, 8 закрепок, 4 формы крапанов, ореолы, боковые камни, 4 поверхности металла, гравировка и декоративные линии. Библиотека содержит 24 образца пропорций и материалов, а не сведения о складских остатках или сертификатах.

Пять сцен: студия, дневной свет, вечер, бархат, каменный постамент. Вращение, масштаб, клавиатурные ракурсы, история до 60 состояний, сравнение A/B, PNG, GLB, сохранение и открытие редактируемого JSON-проекта. Размеры модели задаются в миллиметрах, GLB экспортируется с масштабом 0.001 в метрах.

## Архитектура

- `src/constructor/schema.json`: единый контракт вариантов, диапазонов и значений по умолчанию для JS и Python.
- `src/constructor/stones.json`: общий каталог образцов. Сервер фиксирует выбранный камень по ID, а не доверяет переданным клиентом размерам.
- `src/constructor/catalog.js`: характеристики материалов, готовые направления и сцены.
- `src/ring-design.js`: нормализация, размеры, пояснения и спецификация.
- `src/constructor/design-store.js`: история изменений и объединение событий ползунка.
- `src/parametric-ring.js`: компиляция параметров в BufferGeometry, материалы, сцены и экспорт.
- `src/customizer.js`: интерфейс, предпросмотр AI, файлы, сохранение и заявки.
- `backend/ring_schema.py`: строгая серверная проверка RingRecipe v2 и бюджета геометрии.
- `backend/deepseek.py`: серверный адаптер DeepSeek, системный промпт, изображение, таймауты и ограничение запросов.
- `server.py`: статические файлы и локальные API. Скрытые файлы, исходники сервера и `work/` не раздаются браузеру.

Рендер работает по изменению состояния; отдельный бесконечный цикл не создаётся. Открытый конструктор использует существующий GSAP ticker, закрытый не рендерится. Геометрия старого варианта освобождается, огранки, BVH и материалы кэшируются. Мелкие камни используют тот же материал преломления; мильгрейн использует InstancedMesh. HDRI загружается только при выборе сцены, ограничены DPR и размер карты окружения.

## AI: идея → редактируемый рецепт → 3D

`POST /api/ring-ai` принимает фотографию JPEG/PNG/WebP или описание, необязательные параметры и выбранный образец камня. При наличии фото описание не требуется. Фото уменьшается в браузере до 1600px и остаётся только в памяти текущей страницы. По кнопке и с отдельным согласием описание и референс отправляются сервером в DeepSeek. Исходная фотография и текст не записываются в журнал или на диск.

По умолчанию используется **deepseek-flash** с поддержкой изображений и JSON. `deepseek-v4-pro` разрешён настройкой `DEEPSEEK_MODEL` для текстового ввода. Изображения всегда направляются в Flash. Визуальный ввод требует нескольких запросов; время зависит от изображения и необходимости исправления ответа.

Визуальная обработка разделена на три этапа: независимое распознавание референса, проверка увеличенного фрагмента оправы, извлечение явно заданных текстовых изменений. На фрагменте AI локализует кончики крапанов: четыре сдвоенные позиции не превращаются в восемь равномерных крапанов. Обычное текстовое описание требует только текстового этапа. Контракты и словарь реальных возможностей движка находятся в `backend/ring_prompts.py`.

Сервер собирает рецепт в коде по приоритету: нейтральная основа, уверенно распознанные признаки, явные требования описания, зафиксированный камень библиотеки. От текущего проекта сохраняются размер пальца и сцена; посторонние украшения из него не наследуются. Конфликт выбранного камня с фото, неуверенные признаки и неподдерживаемые элементы показываются в интерфейсе. Текстовые изменения проверяются по буквальным цитатам запроса.

Подготовка `stage: prepare` определяет присутствие центрального камня (`centerStone`), ажур (`openwork`) и характер орнамента. План сборки выбирается по этим признакам: обычное кольцо проходит `shank → mount → setting`, орнаментальное без камня — `shank → ornament`. У кольца без камня не создаются каст, крапаны или бриллиант по умолчанию. Генератор возвращает `pipelineVersion:5`, `generation.kind:freeform` и `design.freeform`.

Орнамент — компактный граф авторских путей: закрученные стебли и листья с переменным сечением, высотой и центральным ребром. Пути оборачиваются вокруг отверстия пальца; промежутки между ними остаются сквозными. Края ажурной основы подгоняются по ширине механически, при сохранении авторских профилей. Прикрепления проверяются, число повторов и элементов ограничено. В браузере детали объединяются в один меш; дополнительных npm-зависимостей, 3D-сервиса и GPU-сервера нет. Это процедурное приближение референса, не точная реконструкция скрытой поверхности и не производственный CAD.

Один запуск автоматически проходит подготовку, шинку, оправу и закрепку. Текущий этап виден в прогрессе; остановленную или неудачную сборку можно продолжить с незавершённой части. Только готовое кольцо сохраняется в проект. После сборки доступны прямые настройки размеров и материалов и корректировка формы через `feedback`: зависимые части пересобираются автоматически. Для свободных деталей интерфейс показывает «AI-форма». Полный ручной редактор и экспорт JSON/GLB сохраняются.

`backend/freeform_schema.py` проверяет авторские станции, выпуклые сечения, связи с обеими сторонами шинки и распределение закрепки. `src/freeform-geometry.js` строит BufferGeometry и подгоняет посадочные контакты к контуру камня. Произвольный JavaScript, Python или GLSL из AI не исполняется. Это визуальный 3D-эскиз, а не сертифицированная производственная CAD-модель.

На этап допускается один запрос исправления контракта. Ошибка генерации не заменяет предыдущую итерацию. Ограничения локального адаптера: два одновременных запроса, 30 AI-операций в час, бюджет времени 180с на операцию, фотография до 2МБ после уменьшения. Анализ изображений кэшируется в памяти максимум на 10 минут; фото не сохраняется. Ключ читается только сервером из окружения или `.env`.

Проверки контракта: `python3 -m unittest discover -s tests -v`.

## Проекты и заявки

Автосохранение проекта — `origin-ring-design-v2` в localStorage; старый v1 читается для миграции. Контактные данные и фото туда не записываются. Заявка хранится локально в закрытой папке `work/ring-requests/<UUID>/` вместе с PNG. Отправка писем и CRM не подключены, интерфейс сообщает об этом прямо.

3D-модель предназначена для обсуждения дизайна и пропорций. Проверка соединений, посадочных мест, минимальных толщин и подготовка производства остаются отдельным этапом ювелирного CAD.
